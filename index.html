NTColorAnalyzer mechanism

From wallpaper atmosphere to deterministic UI tokens.

The plugin does not copy colors directly from a wallpaper. It compresses the source into a perceptual fingerprint, then rebuilds that fingerprint through a fixed token schema.

1. Sampling model

The selected image, frame, or image-filled node is exported as PNG and reduced to a 4 x 4 canvas. Those 16 pixels are the complete analytical input. This makes the result stable and biased toward large color masses instead of texture, tiny highlights, or incidental detail.

2. LCH conversion

Each sampled pixel is converted from sRGB through linear RGB, XYZ, Lab, and finally LCH. LCH separates perceived lightness, chroma, and hue, which maps better to token design than raw RGB channel math.

L = perceived lightnessC = chroma strengthH = hue angle

3. Hue filtering

Hue is only trusted when the sampled pixel has enough chroma. The default threshold is 10. Pixels below that threshold still inform lightness and chroma summaries, but they do not get to push the hue story unless every sampled pixel is effectively neutral.

4. Primary and secondary hue families

Valid hue pixels are grouped into twelve 30 degree bands. Bands are ranked by pixel count, then by hue position. The strongest band becomes primary; the next strongest becomes secondary. Each family exposes median, minimum, and maximum selectors.

5. Hue source resolution

Each token family has its own hue source object. A source such as primary_median is resolved first. Then numeric shift is applied. If cap is true, the shifted hue clamps to 0..360. If cap is false, the hue wraps around the wheel.

"hueSources": {
  "container": {
    "source": "primary_median",
    "shift": 0,
    "cap": false,
    "excludeHue": []
  },
  "accent": {
    "source": "secondary_median",
    "shift": 240,
    "cap": false,
    "excludeHue": ["105-107", "220-240"]
  },
  "chromaThreshold": 10
}

6. Excluded hue ranges

Exclusion happens after source, shift, and cap or wrap. If the resolved hue lands inside an excluded range, it snaps to the closest boundary of that range. Multiple ranges are supported and checked in array order.

106 inside 105-107 -> 105106.7 inside 105-107 -> 107225 inside 220-240 -> 220

7. Token reconstruction

Final colors are generated from the resolved hue plus the JSON settings for each token. Containers, content on solid, content on translucent, content on accent, accent, and alert tokens all use their own lightness, chroma, and opacity rules. Container secondary and tertiary use fixed white or black translucent fills and numeric blur rather than a dynamic LCH color.

8. Grayscale fallback

When no sampled hue passes the chroma threshold, generated dynamic chroma is forced to zero. Container accent then uses its lightness_grey value, so black and white wallpapers keep a controlled neutral accent instead of inventing a colorful accent from noise.

Pipeline summary

  1. Export selected wallpaper or frame as PNG.
  2. Downsample to a fixed 4 x 4 canvas.
  3. Convert each sampled pixel from sRGB to LCH.
  4. Ignore low-chroma hue noise below the threshold.
  5. Pick primary and secondary hue families from 30 degree bins.
  6. Resolve each token family through source, shift, cap, and excluded hue ranges.
  7. Generate final LCH tokens and convert them back to RGB for Figma layers.
